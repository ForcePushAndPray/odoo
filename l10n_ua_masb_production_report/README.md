# Відомість аналітичного обліку по рахунку 23 «Виробництво»

Модуль `l10n_ua_masb_production_report` будує матричну відомість виробничих
витрат — ту саму, що бухгалтер веде за формою розділу III Журналу 5 (регістри,
затверджені наказом Мінфіну від 29.12.2000 № 356), тільки розгорнуту в розрізі
підрозділів.

## Що показує звіт

```
сальдо на початок
  → обороти Дт у розрізі кореспондуючих КРЕДИТОВИХ рахунків
  → Всього по дебету
  → обороти Кт у розрізі кореспондуючих ДЕБЕТОВИХ рахунків
  → Всього по кредиту
  → сальдо на кінець
```

Рядки — три рівні:

1. **субрахунок виробництва** (231, 233, 235, 236…);
2. **підрозділ** — аналітичний рахунок обраного кореневого плану, узятий з
   аналітичного розподілу рядка проводки;
3. **елемент витрат** — матеріали / інші прямі витрати / розподіл витрат минулих
   періодів / загальновиробничі, визначається за кореспондуючим рахунком.

## Встановлення

Модуль ставиться поверх української локалізації й залежить від
`l10n_ua_account_base` та `analytic`.

```
Додатки → оновити список → l10n_ua_masb_production_report
```

## Налаштування

**Колонки.** Бухоблік → Налаштування → Україна → Довідники → «Колонки
відомості по рахунку 23». Кожна колонка — це набір префіксів кореспондуючого
рахунку, блок (дебетовий чи кредитовий) і елемент витрат. Типовий набір
встановлюється разом з модулем і далі належить бухгалтеру: записи позначені
`noupdate`, оновлення модуля їх не перезапише.

Колонки зіставляються від найдовшого префікса до найкоротшого, тож колонку `901`
можна додати поруч із `90`, не змінюючи порядок.

**Аналітика.** У плані, обраному у полі «План підрозділів», мають бути
аналітичні рахунки на кожен цех. Щоб відомість була повною, аналітика на
рахунках 23 має бути обов'язковою: Бухоблік → Налаштування → Аналітичний
бухоблік → Аналітичні плани → вкладка «Застосовність».

## Робота зі звітом

Бухоблік → Налаштування → Україна → «Відомість по рахунку 23 (виробництво)» →
Новий → період → **Розрахувати**. Далі доступні друк (A3, альбомна) і
вивантаження в XLSX.

### Контроль

Поля «Контроль: оборот за дебетом / за кредитом» беруться безпосередньо з
проводок, без відновлення кореспонденції. Якщо вони не дорівнюють підсумкам
відомості, форма показує попередження: значить, у періоді є проводка, обороти
якої не вдалося рознести.

Поле «Без підрозділу» показує обороти, у яких немає аналітики потрібного плану.
Такі суми не зникають — вони йдуть в окремий рядок без підрозділу.

## Два припущення, які варто узгодити з бухгалтером

**Кореспонденція.** Odoo не зберігає пар «дебет-кредит»: проводка — це набір
рядків. Сума кожного рядка розкладається на рядки протилежного боку тієї ж
проводки пропорційно їхнім сумам. Для звичайної проводки «один Дт — кілька Кт»
це точний результат; для «кілька Дт × кілька Кт» точної відповіді не існує
взагалі. Те саме правило застосовують `l10n_ua.account.analysis` і
`l10n_ua.correspondence` в українській локалізації.

**Рознесення кредиту на елементи витрат.** Списання з виробництва саме по собі
не знає, яка його частина була цементом, а яка зарплатою. Кредитові обороти
рознесені між елементами пропорційно їхнім дебетовим оборотам того самого
періоду — так, як це робить паперова відомість. Якщо у вашій обліковій політиці
правило інше, змінювати треба метод `_build_lines`.

## Технічний борг

Правило відновлення кореспонденції відтворене в цьому модулі локально, бо
спільний хелпер `l10n_ua.correspondence` (а) ще не влитий у гілку 19.0
локалізації, (б) не вміє групувати за виміром аналітики. Коли хелпер отримає
параметр виміру, метод `_iter_correspondence` треба замінити на виклик хелпера —
інакше два звіти за той самий період одного дня розійдуться в числах.
